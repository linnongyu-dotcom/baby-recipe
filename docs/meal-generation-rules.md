# 周餐单生成与质量审计规则

## 午餐结构与优先级

12 月龄以上的午餐结构是“主食 + 独立动物性肉菜 + 真实蔬菜 + 尽量有汤”。汤中的肉末、蛋花等不能代替独立肉菜。规则优先级固定为：**年龄、过敏和忌口 > 午餐基本结构 > 周蛋白目标 > 家族和形态多样性 > 汤与其他软偏好**。候选不足时必须先放宽软目标，不能选择冲突食谱，也不能主动让午餐无肉。

## 周蛋白与多样性软目标

- 红肉每周 2～3 次，禽肉 1～2 次，鱼虾 1～2 次；蛋和豆制品只在没有动物性肉菜候选时兜底。
- 同一 recipe ID 优先不重复，同一 family 一周优先一次，同一 cooking form 避免连续。
- 目标均服从实际候选可用性；过敏或忌口导致候选不足时，审计器降级为提示或不报告，绝不能反向突破安全约束。

## 汤规则

普通午餐在有合规候选时尽量配汤；带汤主食不额外配独立汤。含少量蛋白质的汤可以存在，但汤永远不能充当独立肉菜。缺汤是体验警告，而不是阻止餐单使用的硬错误。

## 可重复生成与审计

`generateWeeklyPlan(settings, { seed })` 使用局部随机源；相同资料、食谱和 seed 产生相同餐单，不修改全局 `Math.random`。`auditWeeklyPlan` 是不修改餐单的纯检查函数，调用方应依赖稳定的 issue code，而不是中文 message。

常规测试使用少量固定种子；完整验收运行 `npm run audit:meal-plans`，覆盖 3 个年龄段、6 类档案和每档 100 个种子。失败输出包含年龄、档案、限制、seed、issue code、当天午餐和全周午餐肉菜，可直接复制复现。硬错误令命令返回 1；只有警告仍返回 0。

## 缓存

餐单规则缓存只在确有不兼容结构变更时提升一次。迁移仅清除旧 `weeklyPlan`，保留宝宝档案、过敏、忌口、喜好、收藏与自定义食谱；禁止清空整个 `localStorage`。
